# Dev Request Skill — Minimal Spec

Purpose
- Encode a two-step, solo-dev workflow for change proposals and optional uncommitted edits.
- Ensure the agent never commits or opens PRs; the user manages all git commits with GitHub Desktop.

CLI Triggers / Example Prompts
- "Outline proposed changes for <feature/path>"  (preview-only)
- "Refine proposal: <clarification or constraints>"
- "Create uncommitted edits for the last-approved proposal" (writes files but leaves them uncommitted)

Flags
- --preview-only : produce a human-readable plan or diff-like description, do not modify files.
- --create-uncommitted : after explicit user confirmation, create the edits as uncommitted workspace changes.

Agent Behavior
0. For investigative requests (phrases like "investigate" or "explain" or "report" or "investigate and report" or "report here"), produce a written investigation and explanation in this conversation without making any code changes, workspace edits, or file modifications. Wait for explicit user confirmation before proposing or applying any edits.
1. Always start with a CLI-only proposal (respect --preview-only or default to preview). The proposal must list files to change/create, exact hunks or pseudo-diff, rationale, and risk notes.
2. Ask the user a concise confirmation question: "Refine or approve? (refine/approve)". If user replies "refine", accept refinement instructions and produce an updated proposal.
3. Only when the user explicitly asks for "create uncommitted edits" (or uses --create-uncommitted) generate file edits in the workspace. Never stage, commit, push, or open PRs.
4. When creating edits, ensure they are uncommitted only, do not commit, do not stage, do not create a PR, do not perform any git operations.

Safety & Constraints
- No git operations (commit, branch, merge, push) are performed by the agent.
- Keep changes minimal and surgically scoped to the files listed in the proposal.
- If a requested change touches tests or DB migrations, warn about required local validation steps.

Examples
- Preview-only request:
  - User: "Outline proposed changes for improve-kml-parsing --preview-only"
  - Agent: lists 3 files, shows diffs, and asks "Refine or approve?"

- Create uncommitted edits:
  - After approval, User: "Create uncommitted edits for the last-approved proposal"
  - Agent: writes files, prints the file paths it changed, and shows the top diff. Files include the UNCOMMITTED header.
